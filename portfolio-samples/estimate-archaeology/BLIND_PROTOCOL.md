# 目隠し試験の手順（Blind test protocol）

このフォルダの `blind/` には、架空の会社2社（印刷 `print/`・看板 `sign/`）の過去の見積もり履歴が入っています。
値段の決まり（隠れたルール）と、人の癖（古い単価表の使い回しなど）を混ぜて生成したものです。

## 公正さの担保
- データを作ったエージェントと、ルールを復元する側（solver）は別です。作る側は solver のコードを見ていません。
- 正解（生成器・ルールの説明・1件ごとの正解）は、採点までこのリポジトリの外に置いていました。
- **ただし、技術的に読めない状態ではありませんでした。** 正解は solver の作者・assisted の分析者と同じ作業環境に平文で置かれていて、「読まない」という指示と事後の点検（コード・設定・拡張に正解への参照や個別の見積番号の埋め込みがないこと）で守っていました。読めなかったことの証明ではありません。
- 封印したファイルの SHA-256 を `blind/*/SEALED.sha256` に記録し、**solver のコードより前のコミット**で公開しています。採点のときに封印を開け、ハッシュが一致することを確かめてから正解と照らし合わせます。

## solver が使ってよいもの
- 1週目の試験：`blind/*/quotes.csv` と `SCHEMA.md` だけ。
- `messy/` の Excel は2週目（汚れた Excel の取り込み）で使います。実際の見積書の控えと同じく、明細行や端数調整の行が入っているものがあり、ルールの手がかりになります。これは意図したものとして扱い、使った場合は報告に明記します。
- `messy/` の一部にある「結果（受注・失注など）」の列は、採点の対象外で、solver の入力にも使いません。

## 採点の物差し
- 1円まで一致した件数の割合（あわせて ±100円・±1% も報告）
- ルールから外れた見積もりの検出：適合率・再現率
- 外れを誤って人の癖と判定した件数
- ルールが足りないと判断して判定を止めた件数

数字は封印を開けた後に、ここへ追記します。

## 1週目の結果（2026-10-07 採点）

封印したファイル（生成器・ルールの説明・正解）のハッシュは、すべて `447a2ae` の `SEALED.sha256` と一致しました。
正解は `blind/print/revealed/` と `blind/sign/revealed/` に公開しています。
solver のファイルはまだコミットされていないため、封印より後に作られたことはファイルの更新時刻でしか示せません（一番古いものは封印の12分後）。

| データ | 実行 | 規則どおりの税抜額と1円一致 | ±100円 | ±1% | 正常見積で1円一致 | 逸脱の指摘 | 誤告発 | 判定保留 |
|---|---|---|---|---|---|---|---|---|
| 印刷（2,400件） | frozen | 226（9.4%） | 11.9% | 12.5% | 9.7% | 0（判定停止） | 0 | 2,169 |
| 印刷 | assisted | 469（19.5%） | 22.4% | 24.3% | 20.3% | 0（判定停止） | 0 | 1,933 |
| 看板（2,378件） | frozen | 110（4.6%） | 4.8% | 5.4% | 4.9% | 0（判定停止） | 0 | 2,268 |
| 看板 | assisted | 131（5.5%） | 6.2% | 7.7% | 5.6% | 0（判定停止） | 0 | 2,243 |

- 4つの実行すべてで判定停止が働き、逸脱の分類は1件も出ていません。逸脱の検出は0件（再現率 0%）で、誤告発0件は「何も判定しなかった」結果です。常に判定を保留するだけの仕組みでも同じ数字になるので、これは成果ではありません。
- 参考として、同じルールで判定停止を外すと、指摘の適合率は 5.9〜7.6% でした。非正常の割合（6.4〜6.5%）とほぼ同じで、正しい見積 90〜498件が人の癖とされ、「原因不明」の指摘まで含めると正しい見積 213〜1,260件に指摘が付きます。
- 隠れたルールの復元（正確 / 近似 / 未復元 / 正しく保留）は、印刷33項目で frozen 0 / 9 / 22 / 2、assisted 4 / 11 / 17 / 1、看板30項目で frozen 0 / 5 / 25 / 0、assisted 0 / 9 / 20 / 1 でした。
- 2社とも Claude のエージェントが書いた架空のデータで、生成は各1回、assisted は同じ試験データで改良したものです。詳しくは [`reports/blind-week1.md`](reports/blind-week1.md)、再計算は `python3 scripts/score_blind.py` です。

### この結果から分かったこと
- **1週目の solver は、目隠しのデータでは使い物になりませんでした。** 開発用データ（自作の生成器）では印刷 88.8%・看板 56.9% を再現していましたが、目隠しでは 9.4%・4.6% でした。開発用データの数字は、自作の生成器に合わせ込んだ結果だったということです。
- 届かなかった主な理由は2つです。
  - **探索が弱い。** 分析者が手で書いた式をエンジンで検証すると、看板のインクジェットで164件が一致しましたが、自動の探索は76件でした。
  - **書けない決まりがある。** 「合計がいくら以上なら送料無料」「担当者が1万円以上だけ500円単位で丸める」「最低料金の改定」など、計算した金額に応じて変わる決まりは、今の部品では表せません。
- assisted の数字（印刷 19.5%）は、同じ試験データを見ながら改良したものなので、目隠しの成績ではありません。
