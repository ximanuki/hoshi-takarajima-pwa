# 開発用データ（devdata）

solver を作る側が、solver の動作確認のために書いた生成器と、生成済みのデータです。
**目隠し試験のデータ（`blind/`）とは無関係**で、その値を見ずに作っています（列の並びだけは `blind/*/SCHEMA.md` に合わせています）。

| フォルダ | 生成器 | 内容 |
|---|---|---|
| `print/` | `gen_print.py` | 架空の印刷会社（チラシ・リーフレット・冊子・名刺・封筒）2,434件 |
| `print_heavy/` | `gen_print.py --heavy` | 同じ会社で、文法外のルールが効く見積を大幅に増やしたもの（判定停止の確認用） |
| `sign/` | `gen_sign.py` | 架空の看板会社（アルミ複合板・カルプ文字・インクジェット出力・袖看板）2,410件 |

各フォルダの `truth.csv` に、1件ごとの正解（`label`: clean または癖の種類、`true_net`: 税抜の正しい金額、
`out_of_grammar`: solver の部品で表せないルールが効いているか）が入っています。ルールの詳細は各生成器の先頭の docstring にあります。

**文法の外に置くつもりで入れたルール**（`out_of_grammar=1`）:
- 印刷: チラシの月末（28日以降）3%引き、40ページ以上の冊子の追加料金（16ページごと）
- 看板: 幅 2,400mm を超えるアルミ複合板の継ぎ手料金、インクジェット出力で数量が2以上のときの1枚ごとの最低面積

このうち本当に部品で表せないのは「チラシの月末3%引き」だけでした（設定に日付の「日」の列がないため）。
残りは、ページ数ごとの表（ページ数の値が少ないので表引きになる）、幅のしきい値、1枚ごとの最低面積（最低数量 × 数量）で表せるため、
solver が再現することがあります。結果表の「文法外」の再現率はこの意味で読んでください。

```bash
make devdata    # 生成し直す（固定シードなので同じファイルになる）
make dev-eval   # 全データで fit → 採点 → reports/dev_results.md
```

`evaluate.py` の数字は**開発用の数字**です。生成器と solver を同じ側が書いているので、仕組みが動くことの確認であって、
未知のデータでの精度ではありません。
