## 2. 何と何を比べたか

**正解の税抜額。** truth.csv には2つの税抜額があります。`rule_net` は、隠れたルールを見積の記載どおりの項目に当てた額です。`true_net` は、店が実際に意図した額です。古い表を使った、値引きした、といった癖が入るとこちらが変わります。solver の `predicted_net` は「規則どおりの額」なので、主な物差しは `rule_net` との一致にしました。`true_net` との一致もあわせて示します。正常見積（印刷 2,245件、看板 2,225件）では、2つの額と記載額はすべて一致しています。

**非正常の見積。** 癖のラベルが `clean` でないものです。印刷は 155件（6.5%）、看板は 153件（6.4%）あります。このうち印刷 27件・看板 25件は、金額そのものは規則どおりで記載も正しいものです。再発行前の版、二重入力、規則どおりに計算し直した再発行（看板）がこれにあたります。そこで検出の物差しは2つ用意しました。「非正常すべて」と、記載額が規則から外れている「金額の外れ」（両データとも 128件）です。

**指摘。** solver の `status` が `deviation`（逸脱、分類あり）か `unexplained`（原因不明）のものを「指摘」と数えます。`abstained`（判定保留）は指摘に含めません。

**誤告発。** 正常見積に、人の原因を名指しする分類（`unexplained` 以外の7分類）を付けたものです。`unexplained`（原因不明）も逸脱の指摘の一種なので、正常見積への指摘の総数は「誤告発」と「正常を原因不明に」の合計で見てください。

## 6. ルールの復元

RULES.md の隠れたルールを1つずつ取り出し、各実行の `rules.json` と `rules_ja.md` のどの要素がそれにあたるかを採点者が判定しました。判定の基準は次のとおりです。

- **正確**: 条件・形・値が隠れたルールと同じ要素がある。ただし、ほかの要素の誤りで最終の金額がずれることはある。
- **近似**: 条件（語・キー・境界・日付）は正しいが、値か形が違う。
- **未復元**: 対応する要素がない、または要素はあるが対応しない。
- **保留（正しい）**: 履歴で決められないとして「要聞き取り」にしており、真値が示した範囲に入っている。

| データ | 項目数 | frozen: 正確 / 近似 / 未復元 / 保留（正しい） | assisted: 正確 / 近似 / 未復元 / 保留（正しい） |
|---|---|---|---|
| 印刷 | 33 | 0 / 9 / 22 / 2 | 4 / 11 / 17 / 1 |
| 看板 | 30 | 0 / 5 / 25 / 0 | 0 / 9 / 20 / 1 |

## 7. 目立った失敗の例

1. **正しい見積を「打ち間違い」と判定する（判定停止なしの参考値）。** 看板 2210-074 は、インクジェット 1,030×1,456mm 透過フィルム4枚、新規デザイン、現地調査あり、税別63,000円で、規則どおりの見積です。frozen の規則はこれを6,000円（最低料金）と予測し、「規則どおりなら 6,000 のところ 63,000 と記載（桁の脱落・重複）」と分類しました。本番では判定停止で保留になっています。
2. **正常な見積を「記録のない値引き」とする（同じく参考値）。** 印刷 Q2210-005（C035、A4 16頁 500部、データ修正あり、40,400円）は規則どおりです。frozen の規則は44,020円と予測し、「3,620円の端数調整、条件の記録なし」と分類しました。判定停止なしの誤告発で一番多いのは、この「記録のない値引き」と「記録のない割増」です。どちらも、規則の予測が外れた差をそのまま人の癖として説明したものです。
3. **古い掛率の見積を「正しい」とする（本番の出力）。** 印刷の C003 は、2024-01-01 から掛率が0.95です。Q2404-001（冊子、124,000円）は旧掛率1.00のまま出されています（規則どおりなら117,500円）。両方の実行とも C003 の掛率を1.00としたため、この見積を「再現」と判定しました（Q2402-026 も同じ）。掛率の表に版がないので、改定前の値と改定後の値のどちらかしか持てず、多いほうの癖を規則として覚えてしまいます。
4. **打ち消し合う大きな係数。** assisted の印刷の名刺には、kinds と persons_eff に ±40万円前後の係数があります。看板の袖看板には、ceil(面積,0.1)×数量 に 64万〜73万円、別の項に −47万〜−55万円があります。frozen の印刷の冊子には、ページ数×サイズ別に −1,260,600円 があります。見積の一部は再現しますが、`rules_ja.md` は仕様書として読めません。一致の数を増やすために近い特徴量どうしを当てはめた結果で、assisted の round4.md もこれを注意として書いています。
5. **真の表にない値の断定。** frozen の看板は「袖看板の最低料金165,000円」を採用しました。3件の一致が増えるという理由です。真の最低料金は5,000・6,000円で、袖看板（最も小さい区分で85,000円）では一度も発動しません。
6. **掛率の向きの誤り。** frozen の印刷は、代理店 D の区分の掛率を1.10（真値0.75〜0.85）、個人 K を0.80（真値1.00）としました。掛率は、掛率で歪んでいない「素の見積」と比べて読み取る設計です。ところが素の見積の価格自体が外れているため、掛率がほかの誤差を吸収しています。
7. **税表示の読み違い。** 印刷 Q2210-002（C006、税表示は空欄、16,530円、正しくは税抜）を、frozen は税込と読んで15,028円としました。インボイス前は、空欄が税抜か税込かが得意先の区分で決まっていました。frozen はこれを規則として持たず、見積ごとに読みを選んだため、空欄の正常見積371件中128件を誤読しました。
8. **部品（文法）の外にあるルール。** 配送料の「小計1万円以上は無料」、高橋の「1万円以上だけ500円単位」、看板の田中の「3万円以上は1,000円切り捨て」（正常見積398件）、インボイス前の「税込額の100円切り捨て」は、どれも計算した金額で条件が変わります。v0 の部品では表せません。assisted の分析者は印刷の配送料と高橋の条件に気づいていましたが、拡張では入れられませんでした。
9. **候補に入っても残らなかったもの。** 色校の +8,000円（分析者が例を挙げた）、ハトメの式、現地調査・処分のフラグは、候補に入れても最終のルールに残りませんでした。看板では、分析者が書いたインクジェットの式を手で `Program` にすると164件を再現しますが、探索が選んだルールは76件です（`assist/sign/round4.md`）。探索が、表せるルールを見つけられていないことを示しています。

## 8. この数字が示すこと・示さないこと

**示すこと**

- v0 は、この2社の隠れたルールを円単位ではほとんど復元できませんでした（正常見積で 4.9〜20.3%）。開発用データでの数字（目隠し用の設定で 88.8%・56.9%）は、作者がルールの形を知っているデータでの値で、未知のデータでの精度を表していませんでした。README にもそう書いてありましたが、差はこれほど大きいものでした。
- 判定停止は4つの実行すべてで働き、誤告発は0件でした。ただしこれは「何も判定しなかった」結果で、常に保留するだけの仕組みでも同じ数字になります。成果として数えられるのは、止めなければ正しい見積 213〜1,260件に指摘が付いていたのを防いだ点だけです。
- LLM の分析者が残差を見て候補を書くと、印刷では一致が倍になりました（226件から469件）。ただし、同じ試験データを見ながら4回改良した結果なので、目隠しの成績ではありません。分析者が式を書いた部分は値まで合いました（改定日、名刺の片面PP、名刺の修正料、特急の ×1.25）。看板ではほとんど変わりませんでした（110件から131件）。

**示さないこと**

- **一般性。** 2社とも、私たち（Claude のエージェント）が書いた架空の会社です。実在の会社の見積の難しさを代表しているかは分かりません。ルールが実務より整いすぎている可能性も、複雑すぎる可能性もあります。
- **ばらつき。** 業種ごとに1回だけ生成したデータです（印刷 seed 7310429、看板 seed 521031）。別のシードや別の会社でどれだけ変わるかは測っていません。
- **独立性。** 生成器、solver の作者、assisted の分析者、この採点者は、すべて Claude のエージェントです。別系統のモデルや人が作ったデータではないので、どんな癖を入れるか、どう書くかについて、同じ思い込みを共有しているかもしれません。担保しているのは「生成側は solver のコードを見ていない」ことと、封印のハッシュだけです。
- **assisted の汎化。** assisted は同じ試験データで3〜4回改良した結果で、未知のデータでの成績ではありません。分析者は正解を見ていませんが、試験データの残差は見ています。
- **ルール復元の判定。** 「正確・近似・未復元・保留」は採点者の判断です。根拠は表に書きましたが、別の人が見れば一部は変わりえます。特に「近似」は幅が広く、「語は正しいが値は大きく違う」ものも含みます。
- **分類の質。** 本番の出力には分類がなく、分類の質は測れていません。判定停止なしの参考値でも、分類の正解率の分母は17〜104件と小さいです。
- **時刻の順序。** solver のコードと出力はまだコミットされていません。封印より後に作られたことは、ファイルの更新時刻でしか示せません。
- **範囲。** `messy/` の Excel は使っていません（2週目の範囲）。

## 9. 再現の手順

```bash
# 採点（正解は blind/<domain>/revealed/ から読み、447a2ae のハッシュと照合してから採点する）
python3 scripts/score_blind.py --json reports/blind-week1.json

# 参考値（判定停止なし）を作る場合。同じ rules.json を当て直すだけで、再当てはめはしない
export PYTHONPATH=src OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
.venv/bin/python -m estimate_archaeology.cli check --rules runs/frozen/print/rules.json   --config configs/blind_print.json --quotes blind/print/quotes.csv --threshold 0 --out runs/grading/threshold0/frozen/print
.venv/bin/python -m estimate_archaeology.cli check --rules runs/frozen/sign/rules.json    --config configs/blind_sign.json  --quotes blind/sign/quotes.csv  --threshold 0 --out runs/grading/threshold0/frozen/sign
.venv/bin/python -m estimate_archaeology.cli check --rules runs/assisted/print/rules.json --config configs/blind_print.json --quotes blind/print/quotes.csv --threshold 0 --extensions assist/print/round4 --out runs/grading/threshold0/assisted/print
.venv/bin/python -m estimate_archaeology.cli check --rules runs/assisted/sign/rules.json  --config configs/blind_sign.json  --quotes blind/sign/quotes.csv  --threshold 0 --extensions assist/sign         --out runs/grading/threshold0/assisted/sign
```

`runs/` は git の対象外です。採点に使った `predictions.csv` と `rules.json` のハッシュは、`reports/blind-week1.json` の `scored_files` にあります。
ルール復元の判定とその根拠は、`scripts/score_blind.py` の `RECOVERY` にデータとして書いてあります。
