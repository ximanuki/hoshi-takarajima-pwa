# 問い合わせ・予約フォームの自動返信＋チャット通知＋対応管理（Google Apps Script）

小さなお店・個人事業向けのテンプレートです。Googleフォームに届いた問い合わせ・予約について、お客様への自動返信、Slack / Discord / Chatwork への通知、対応状況の管理をまとめて行います。
文面や通知先はスプレッドシートの「設定」「返信テンプレート」シートで変えられるので、コードを触る必要はありません。

## できること
| タイミング | 動き |
|---|---|
| フォームが送信されたとき | お客様に自動返信メール（「予約」「見積」「その他」など種別ごとに文面を切り替え） |
| 〃 | Slack / Discord / Chatwork に新着を通知（使うものを「する」にするだけ。複数同時も可） |
| 〃 | 回答シートの「対応状況」を「未対応」にし、「処理ログ」に返信・通知の結果を記録 |
| 〃（スパム疑いのとき） | メールアドレスが不正、または NGワードを含む送信は「スパム疑い」にして、返信も通知もしない |
| 毎日 9時 | 「未対応」のまま24時間（変更可）たった問い合わせをチャットでリマインド |
| いつでも | 「対応状況」（未対応／対応中／完了／スパム疑い）と「担当」をプルダウンで更新。状況ごとに色分け |

現場で困りやすい点への対策:
- 全角で入力されたメールアドレス（`ｔａｒｏ＠ｅｘａｍｐｌｅ．ｃｏｍ`）は半角に直して送信。docomo・au の古い形式（ドットの連続など）も受け付ける
- 受付番号は受付日時から作るので、シートを並べ替えても変わらない
- フォーム送信のトリガーが二重に起動しても、返信・通知は1回だけ
- 回答に `@everyone`・`<!channel>`・`[toall]` が書かれていても、チャットで全員あての通知にならない
- 1つの通知先が失敗しても、ほかの通知先と自動返信は続ける（混雑時は1回だけ再送）
- Chatwork の APIトークンはシートに書かず、スクリプトプロパティに保存
- メニュー「設定をチェック」で、質問名や URL の書き間違い、テンプレートの差し込み名のタイプミスを知らせる

## 設定手順（概要）
1. Googleフォームを作り、回答をスプレッドシートにリンクする
2. スプレッドシートの「拡張機能」→「Apps Script」を開き、`Code.js` の中身を貼り付ける
3. `setupAll` を1回実行し、権限を許可する（「設定」「返信テンプレート」シート、管理用の列、トリガーができる）
4. 「設定」シートで店舗名と通知先を、「返信テンプレート」シートで文面を編集する
5. メニュー「問い合わせ管理」→「テスト通知を送る」「自動返信のテストメールを送る」で確認する

画面ごとの詳しい手順は [SETUP_GUIDE.md](SETUP_GUIDE.md) にあります。

## シートの構成
**設定**（A列: 項目 / B列: 値 / C列: 説明）
店舗名、フォームの質問名（お名前・メールアドレス・種別）、自動返信のする／しない、差出人名、返信先、BCC、署名、各チャットのする／しないと URL、リマインドの時間、NGワード、担当者リスト。

**返信テンプレート**（A列: 種別 / B列: 件名 / C列: 本文）
- `{お名前}` のように、フォームの質問のタイトルを `{}` で囲むと回答が入る。ほかに `{店舗名}` `{署名}` `{受付番号}` `{受付日時}` が使える
- フォームにない項目は空欄になる（「設定をチェック」で見つけられる）
- 種別は 完全一致 → 部分一致（「ご予約」→「予約」）→「その他」の行 の順に選ぶ

**回答シート**（右端に自動で追加）
`対応状況`（プルダウン・色分け）/ `担当`（担当者リストのプルダウン）/ `処理ログ`（いつ・何をしたか。エラーの理由もここに出る）

## 必要な権限（appsscript.json）
| スコープ | 使いみち |
|---|---|
| `spreadsheets.currentonly` | このスプレッドシートだけを読み書きする |
| `script.send_mail` | 自動返信メールを送る |
| `script.scriptapp` | フォーム送信時・毎朝のトリガーを登録する |
| `script.external_request` | Slack / Discord / Chatwork に送る |
| `script.container.ui` | メニューと確認ダイアログを出す |

## テスト
```bash
npm test
```
- 前半は Google のサービスを使わない関数のテストです（差し込み、Slack / Discord / Chatwork の送信データの形、スパム判定、未対応の抽出（固定の日時）、設定チェックなど）
- 後半は SpreadsheetApp・MailApp・UrlFetchApp などをモックにして、初期設定 → フォーム送信 → 返信・通知 → リマインドの流れを確認します
- 実際の Google・Slack・Discord・Chatwork との通信は、SETUP_GUIDE の「8. 動作テスト」で確認します

## 実案件への流用
- 列名・状態名・リマインドの時刻は `CONFIG`、設定シートの項目と初期値は `DEFAULT_SETTINGS`、初期の文面は `DEFAULT_TEMPLATES` にまとめてあります
- 通知はサービス共通の形（タイトル＋項目＋リンク）から各サービスの形式に変換しています。Google Chat などを足すときは `buildSlackPayload` と同じ形の関数を作り、`buildNotifyRequests` に1行加えます
- スパム判定の条件（URLの数、特定ドメインなど）を増やすときは `checkSpam` に理由を足すだけで、処理ログにもそのまま出ます
