# サンプルデータ生成器（data-gen）

転嫁デスクのデモで使う**架空の**データを作るスクリプトです。

> **すべて架空のデータです。** 会社名・得意先名・仕入先名・商品・価格・取引はすべて作り物で、実在の企業・団体・人物・取引とは関係ありません（名前がたまたま一致しても無関係です）。
> 1社（架空商事株式会社）の自社データという想定で、他社の価格データは含みません。

## 作り方

```bash
cd data-gen
npm run gen      # public/sample/ と data-gen/truth/ を作る（約30MB、数秒）
npm run verify   # 下の「確かめていること」をすべて確認する
```

- Node.js 22.18 以上が必要です（TypeScript をそのまま実行します）。それより古い Node では `npx tsx generate.ts` で動きます。
- 乱数は固定シードで、時計・ロケール・`Math.random` を使いません。何度作っても、どのタイムゾーンで作っても**同じバイト列**になります。
- 生成物（`public/sample/` と `data-gen/truth/`）は大きいのでリポジトリには入れず、このコマンドで作り直します。
- `node generate.ts --out <フォルダ>` とすると、`<フォルダ>/public/sample` と `<フォルダ>/data-gen/truth` に書き出します。

### 確かめていること（`npm run verify`）

1. 売上明細の A形式と B形式を読み込んで正規化すると、全行が一致する（全角/半角・和暦/西暦・品番ゆれ・半角カナを吸収できている）。
2. 特値一覧と新単価マスタも、A形式と B形式で一致する。
3. 公開ファイルだけを使って `lib/rules.ts` の判定ルールを当てると、正解ファイル（`truth/`）と1行残らず一致する。
4. もう一度生成して、すべてのファイルがバイト単位で一致する（決定性）。

生成時にも、埋め込んだ「漏れ」をルールが意図どおりに判定できるかを1行ずつ確認していて、食い違うと生成を止めます。

## 販売管理の2つの形式

どちらも架空の販売管理システムの CSV 出力です。実際の CSV 出力は Shift_JIS が多いですが、GitHub でも読めるようにサンプルは UTF-8 にしています。

| | 販売管理A（売上明細一覧） | 販売管理B（売上データ） |
|---|---|---|
| 文字コード・改行 | UTF-8（BOM付き）・CRLF | UTF-8（BOMなし）・LF |
| 囲み | 全項目を `"` で囲む | 必要なときだけ |
| 日付 | 和暦 `R07/04/01`（特値一覧は `令和7年4月1日`） | `20250401`（特値の期限なしは `99991231`） |
| 得意先コード | 全角・6桁ゼロ埋め `００１００１` | 半角・ゼロなし `1001` |
| 商品コード | 全角。営業所ごとに書き方が違う：本社 `ＤＢ－１００１`、大阪 `ＤＢ１００１`、名古屋 `ＤＢー１００１`（長音記号） | 半角。入力のゆれあり：`DB-1001`、`DB1001`、`db-1001`、末尾に空白、`DB－1001` |
| 商品名・単位 | 英数字も全角 | カタカナは半角カナ |
| 得意先名 | 正式名 `株式会社星砂工業` | 略称 `(株)星砂工業` |
| 掛率 | `72.0`（%、小数1桁） | `0.720` |
| 金額 | 3桁区切り `"12,800"`、原単価は `1,234.50` | 区切りなし |
| 返品 | 取引区分 `返品`、数量・金額はマイナス | 売上区分 `2`、数量・金額はマイナス |
| 単価の種類 | 単価区分 `標準`／`得意先`／`手入力` | 単価種別 `0`／`1`／`9`（同じ意味） |
| 運賃 | 商品コード `９９９９`（商品マスタにない行） | `9999` |

**列（A）** 売上日, 伝票番号, 行, 取引区分, 部門, 得意先コード, 得意先名, 商品コード, 商品名, 数量, 単位, 定価, 掛率(%), 単価, 金額, 原単価, 原価金額, 粗利額, 単価区分, 備考

**列（B）** 伝票日付, 伝票No, 明細No, 得意先CD, 得意先略称, 品番, 品名, 売上区分, 数量, 単位, 標準価格, 掛率, 売単価, 売上金額, 原価単価, 原価金額, 単価種別, 摘要

- 「定価」「標準価格」は、その日にシステムに登録されていた定価です（2025年4月1日からは得意先に関係なく新定価）。
- 「掛率」は 単価 ÷ 定価 を出力したものなので、ランクの値ちょうどにはなりません。判定には使わないでください。
- 「単価区分＝得意先」は得意先別単価（特値や個別登録の単価）です。大口の得意先は正しい単価でも得意先単価で登録されていることが多く、それだけでは漏れの手がかりになりません。

### 正規化のしかた（`lib/importers.ts`・`lib/text.ts`）

- 商品コード：NFKC → 大文字 → 空白とハイフンの仲間（`-‐‑‒–—―−ー－ｰ`）を取り除く。`ＤＢ－１００１`・`db-1001 `・`ＤＢー１００１` → `DB1001`。商品マスタのコードも同じように変換して突き合わせます。
- 得意先コード：NFKC → 数字だけ → 6桁ゼロ埋め。`００１００１`・`1001` → `001001`。
- 日付：`R07/04/01`、`令和7年4月1日`、`20250401`、`2025/4/1` などを西暦に。
- 文字列（商品名・備考）：NFKC で全角英数字と半角カナをそろえる。
- 金額：3桁区切りを外す。原単価は小数2桁まで。

## 価格と原価のルール

- **単価 = 定価 × 掛率、円未満切り捨て。** 掛率は得意先マスタの値（ランクの範囲内）。
- **定価の丸め**：1,000円未満は10円、1万円未満は50円、それ以上は100円単位。改定時は切り上げ。
- 原単価は1/100円まで。原価金額 = 原単価 × 数量 を円未満四捨五入。
- 前回改定では、仕入値上げ率より少し高い率で定価を上げたので、正しい単価なら粗利率は下がっていません。
- 特値は「その得意先・その商品・その期間だけの単価」。期間中は定価が変わっても特値のままが正しく、期間が終わったら 定価 × 掛率 に戻るのが正しい。

## 埋め込んだ「利益漏れ」（正解は `truth/`）

各行に「正しい単価」を決めて、それと請求単価を比べます。判定の順番は `lib/rules.ts` のとおりで、上で当てはまったものが優先です。

1. 商品マスタにないコード（運賃）、返品（数量マイナス）、無償品（単価0円で、備考に「見本」「サンプル」「無償」「試供」のどれかがある行。見本品を含む）は対象外。0円でも備考にこれらの言葉がない行は、下の手順で判定する。
2. **正しい単価**を決める：期間内の特値があればその特値。なければ 定価 × 掛率（切り捨て）。ここでの定価は、前回改定の合意状況（適用日・据え置きカテゴリ・見送り）で決まる、その得意先に適用すべき定価。
3. 請求単価が正しい単価と同じ → 正常。ただし粗利率が下限（10%）未満なら **粗利下限割れ**。請求単価が正しい単価より高い → 利益漏れに数えない（`overcharge`、基準より高い請求）。ただし粗利率が下限未満なら **粗利下限割れ**。
4. 備考に数量値引の記載（例：`数量値引3%`、`まとめ買い5%引`）があり、正しい単価 ×（100−値引率）% の切り捨てと同じ → 正常（数量値引）。
5. 新定価に移っているはずの日に、旧定価 × 掛率 で請求 → **反映漏れ**。
6. 期間が終わった特値と同じ単価で請求 → **特値の期限切れ**。
7. 請求単価が 定価 × ランクの下限〜上限（それぞれ切り捨て）の外 → **掛率ランク外**。正しい単価より高い請求（ランクの上限を超える請求や、定価の値下げのあとも前の高い定価で請求した行など）は、手順3で除いてあり、利益漏れに数えない（`overcharge`）。そのため上限より上で当たるのは、正しい単価そのものが上限より上（得意先の掛率や特値がランクより高いとき）で、それより安く請求した行だけ。
8. それ以外 → 原因不明の価格差（このデータには0件）。

| 種類 | 得意先×商品 | 行（うち直近12か月） | 影響額（直近12か月） | 埋め込み方 |
|---|---:|---:|---:|---|
| 反映漏れ（旧価格のまま） | 211 | 1,071（643） | 約220万円 | 得意先単価を更新し忘れ。2社は得意先まるごと（うち1社は2026年2月に修正済み）、ほかに約80組（15組は途中で修正済み） |
| 特値の期限切れ | 30 | 278（252） | 約98万円 | 期限が切れた特値のまま請求（5組は途中で修正済み） |
| 掛率ランク外 | 96 | 451（366） | 約121万円 | 2社は販売管理の得意先マスタの掛率が誤り（得意先まるごと）、ほかに35組は受注入力時の手入力単価（8組は途中で修正済み） |
| 粗利下限割れ | 73 | 279（260） | 約20万円 | 2026年4月の仕入値上げ後も定価据え置きで、代理店ランクの粗利が10%未満に（約60組）。粗利が下限を下回る特値（12組） |

- 影響額は、反映漏れ・期限切れ・ランク外では（正しい単価 − 請求単価）× 数量、粗利下限割れでは（粗利10%になる単価 − 請求単価）× 数量。「直近12か月」は2025年10月〜2026年9月で、年間の影響額として使えます。
- 反映漏れの行が同時に粗利下限も割っていることがあります（`truth/lines.csv` の `below_floor`）。種類は上の順番で1つに決めています。
