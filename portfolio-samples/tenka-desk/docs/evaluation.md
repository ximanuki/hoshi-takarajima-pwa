# 漏れ検出の評価（架空データ）

`src/engine` の利益漏れ検出と反映チェックを、サンプルデータの正解（`data-gen/truth/`）と比べた結果です。

## 先に結論

- 架空データでは、4種類の漏れすべてで適合率・再現率とも 100%、年間影響額も正解と1円単位で一致しました。
- **これは実データでの精度を示す数字ではありません。** サンプルデータと検出ルールは同じプロジェクトで作っていて、どちらも `data-gen/README.md` に書いた同じ価格ルールにもとづいています。100% は「エンジンが文書化したルールどおりに動いている」ことの確認です。
- 実データでの精度は、実際の販売管理データで試すまでわかりません（下の「この評価でわからないこと」を参照）。

## 評価のしかた

```bash
npm run sample     # cd data-gen && npm run gen（public/sample/ と data-gen/truth/ を作る）
npm run evaluate   # node scripts/evaluate.ts（表を表示し、docs/evaluation-results.json に書き出す）
```

- エンジンが読むのは `public/sample/` の公開ファイルだけです。正解ファイルは `scripts/evaluate.ts` が採点のためだけに読みます。
- 売上明細 56,328行（2024年10月〜2026年9月）を、販売管理A形式とB形式のそれぞれで診断しました。2つの形式の結果は1行も違いませんでした。
- 「行」は売上明細1行ごと、「組」は得意先×商品×漏れの種類ごとの一致です。1行に複数の問題があるときは、エンジンの優先順（反映漏れ → 特値の期限切れ → 掛け率ランク外 → 粗利下限割れ）で1つに決めて比べています。
- 年間影響額は直近12か月（2025年10月〜2026年9月）の不足額の合計です。
- 実行環境：Node.js 22.22.0。計算は整数だけで行い、時計・乱数・ロケールを使わないので、何度実行しても同じ結果になります。

### 新単価マスタの再現（漏れ検出の評価ではありません）

公開ファイル（次回改定の新定価表と協議結果）から新単価マスタを作り直し、サンプルの新単価マスタと比べました。

| 現単価の決め方 | 行数 | 完全一致 | 単価が違う | 片方にしかない |
|---|---:|---:|---:|---:|
| 販売管理の現在の単価（既定） | 2,748 | 2,742 | 6 | 0 |
| 直近の請求単価 | 2,748 | 2,704 | 44 | 0 |
| 正しい現在の単価 | 2,748 | 2,632 | 116 | 0 |

残る6行は、売上データだけでは知りようがない差です。

- 5行：得意先単位の反映漏れが2026年2月に直った得意先で、直った後に一度も売れていない商品。データ上は旧価格のままに見えます。
- 1行：販売管理の掛率が誤っている得意先で、特値が2026年9月末で切れた商品。切れた後の請求がまだないため、販売管理がどの単価にするかはわかりません。

新単価マスタの B形式の書き出しは、サンプルの B形式ファイルとバイト単位で一致します（`src/engine/sample.integration.test.ts`）。

## 評価の途中で変えたこと

正直に記録しておきます。

- **漏れ検出のルールは、評価を見てから変えていません。** 最初の実行から上の表と同じ結果でした。ただし、ルールを書く前に `data-gen/lib/rules.ts`（正解の定義）と `data-gen/README.md` を読んでいます。そのため、この評価は独立した検証ではありません。
- **得意先まるごとの判定**：最初は「直近12か月に買った商品のうち、問題のある商品の割合」で判定していて、2026年2月に直った得意先（001251）を見落としました（47/75 = 63%）。「問題が続いていた期間に買った商品のうちの割合」に変えて、4社とも示せるようになりました（001251 は 64/73）。正解の得意先コードを使ったものではありませんが、評価結果を見てから変えた点です。
- **新単価マスタの現単価**：最初は直近の請求単価を使っていて、44行が違いました。特値が切れた後の単価を反映できていなかったためです。「漏れが続いている組は直近の請求単価、それ以外は正しい単価」に変えて、6行になりました。

## エンジンのルールと正解ルールの違い

エンジンは一般的なルールとして書いたので、正解ルールと少し違うところがあります。このデータでは結果に差が出ませんでした。逆にいうと、このデータはこれらの違いを試せていません。

- 数量値引：基準単価から値引率を引いた単価の端数処理を、切り捨て・四捨五入・切り上げのどれでも認めます（正解ルールは切り捨てだけ）。
- 粗利下限割れ：数量値引の行も粗利率を確かめます（正解ルールでは数量値引の行は正常）。このデータには該当行がありませんでした。
- 掛け率ランク外：ランクの上限を超える請求（過大請求）も「ランク外」として示し、影響額はマイナスで表します。年間影響額の合計には含めません。
- 定価の変更：合意状況の記録がない定価の変更でも、旧定価のままの請求を反映漏れとして示します。
- 見本品：備考の「見本」「サンプル」に加えて「無償」「試供」でも見本品とみなします。
- 「継続中」：正解は「埋め込んだ漏れが直っていないか」で数えますが、エンジンは「その組の最後の請求がまだ漏れか」で判断します。反映漏れの継続中は、正解 132組に対してエンジン 145組です。直った後に売れていない組は、データからは直ったかどうかわからないためです。

## この評価でわからないこと

- 実際の販売管理データでの精度。実データには、このサンプルにない状況がありえます。
  - 価格改定が何度も重なる、期間の途中で単価が変わる、得意先の掛率が途中で変わる
  - 単価に小数がある（銭単位）、重さや長さで売る商品、税込単価
  - 値引やリベートが別の行や後日の伝票で計上される
  - 店舗別・納品先別の単価、同じ商品の複数の特値
  - 列名やコードの書き方が、この2形式とまったく違う販売管理システム
- 「原因不明の価格差」は、このデータには1行もありません。実データでは、ここに分類される行の扱いが大事になります。
- 年間影響額は直近12か月の実績で、これからの予測ではありません。
- 正解データは架空の会社（架空商事株式会社）のものです。実在の企業・取引とは関係ありません。
