# gen-4：包装資材・紙製品メーカー（直販と代理店）のブラインド評価用データ

**このフォルダのデータはすべて架空です。** 会社名（白波紙工株式会社）、得意先名、仕入先名、商品、価格、担当者名、取引は作り物で、実在の企業・団体・人物・取引とは関係ありません（名前がたまたま一致しても無関係です）。

転嫁デスクの README と data-gen/README.md（文書）だけを読んで、エンジンや既存のサンプル生成器を見ずに作った、独立のテストデータです。

## 架空のシナリオ

- 自社：**白波紙工株式会社**（架空）。段ボールケース・紙器（化粧箱）・紙袋・包装紙・紙管・紙製緩衝材・紙製食品容器・ラベルを自社3工場（本社工場・関東工場・関西工場）で作り、テープ・結束資材とポリ袋・フィルムは仕入品として扱う。営業拠点は本社営業部・北関東営業所・中部営業所・関西営業所。
- 販路：代理店（包装資材商社・二次卸。掛率ランク S）への卸と、食品製造・化粧品・医薬品・通販・印刷・物流・農業・工業・小売への直販（ランク A〜D）。
- 期間：売上明細は **2025年1月〜2026年9月（令和7年1月〜令和8年9月）の21か月**。直近12か月は 2025年10月〜2026年9月。
- 定価改定：全社的な定価改定が2回ある（2025年4月1日と2026年4月1日。詳しくは下の「利用者が知っていること」）。ほかに、ポリ袋4点の値下げ（2025年10月）、テープ8点の個別値上げ（2026年8月）、新商品の発売、廃番がある。
- 原価：2025年4月に原紙などの原価が上がり、2026年7月に原紙の再値上げと仕入先（テープ）の値上げがあった（2026年7月の分は定価据え置き）。仕入先からは、2026年12月・2027年1月適用の値上げ通知が来ている。
- 次回改定（`next/`）：2026年12月1日（令和8年12月1日）に新定価へ切り替える想定で、新定価表、新単価マスタ、2026年12月分の売上明細を入れている（反映チェック用）。

## 作り方

```bash
node generate.mjs --data <入力フォルダ> --sealed <正解フォルダ>
```

- Node.js 22 で動きます。依存パッケージはありません。
- 乱数は固定シードで、時計・ロケール・`Math.random` を使いません。2回作って、入力ファイルも正解ファイルもバイト単位で一致することを確かめてあります。
- Shift_JIS は、Node の `TextDecoder('shift_jis')` を逆引きして作った CP932 エンコーダで書いています。
- 正解（`truth/lines.csv`、`truth/followup_lines.csv`、`truth/summary.json`、`notes.md`）は正解フォルダに書き、`SEALED.sha256` に sha256 を入れてあります。正解は、生成の意図ではなく、**公開ファイルの内容に文書のルールを当てて**1行ずつ決め、意図と食い違う行があれば生成を止めるようにしています。

## 利用者が知っていること

実際にこのアプリを使う担当者が、正解ファイルを見なくても知っていることです。

- **前回の定価改定日は 令和8年4月1日（2026年4月1日）** です。`令和8年度価格改定_得意先回答状況.csv` はこの改定についての回答で、申入れは2026年1月下旬〜2月、回答は2月〜3月に集まりました。
- その前の全社的な定価改定は 令和7年4月1日（2025年4月1日）で、こちらの回答状況のファイルは残っていません（全得意先に適用した扱い）。
- 粗利率の下限は 10%。単価は 定価 × 掛率 の円未満切り捨て。
- 特値は得意先×商品×期間の単価で、年度（4月〜3月）単位の契約が多く、2026年4月に更新したものと、更新せずに終わったものがあります。
- 合意状況の「適用日」が空欄の「合意」は改定日からの適用、「協議中」の適用日「未定」は未定のままです。
- 2026年7月に原紙と仕入テープの原価が上がりましたが、定価は据え置きました（12月の改定で反映する予定）。テープ8点だけ2026年8月1日に個別に定価を上げています。
- 商品マスタにない `9999`（運賃）・`9998`（抜型代）・`9997`（版代）は商品ではありません。
- 得意先マスタ（`得意先マスタ.csv`）の掛率ランクと掛率が、取り決めどおりの値です。

## 注意

- 正解の内容（どの行が漏れか、金額）はこの README には書いていません。`blind2-sealed/gen-4/` を見てください。
- 文書だけでは読み方が1つに決まらない行は `label=ambiguous` にし、`ambiguity` 列に2つの読み方を書いています（全体の0.1%未満）。
