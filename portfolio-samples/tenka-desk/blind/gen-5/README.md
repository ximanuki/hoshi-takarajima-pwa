# gen-5 テストデータ（架空）：機械部品・工具の商社

**すべて架空のデータです。** 会社名・得意先名・仕入先名・商品・価格・取引は作り物で、実在の企業・団体・人物・取引とは関係ありません（名前がたまたま一致しても無関係です）。

### 書式のくせ（実際の書き出しに合わせたもの）

- 売上明細と特値一覧は、全項目を `"` で囲み、得意先コード・商品コード・商品名の英数字は全角。日付は和暦（売上明細 `R06/09/02`、特値一覧 `令和7年4月1日`）、金額は3桁区切り。
- 売上明細の商品コードは営業所ごとに書き方が違う（本社営業部 `ＢＲ－１００１`、北営業所 `ＢＲ１００１`、南営業所 `ＢＲー１００１`）。ほかに、末尾に全角空白が付いたもの、小文字のものがまれにある。
- 売上明細の列：売上日, 伝票番号, 行, 取引区分（売上／返品）, 部門, 得意先コード, 得意先名, 商品コード, 商品名, 数量, 単位, 定価, 掛率(%), 単価, 金額, 原単価, 原価金額, 粗利額, 単価区分（標準／得意先／手入力）, 備考。「定価」はその日にシステムに登録されていた定価、「掛率(%)」は 単価÷定価 を出したもの。
- 運賃・代引手数料・出精値引は商品マスタにないコード（`Z-001`・`Z-002`・`Z-009`）。
- マスタ類（得意先・商品・定価履歴・原価履歴）の日付は `2024/10/01`、Excel で管理している一覧（合意状況・協議結果・新定価表）は `2025/7/1`。Excel を通ったので、合意状況と協議結果の得意先コードは先頭の0が落ちている（`010020` → `10020`）。
- 伝票番号は売上明細の期間をまたいで通し番号。2026年9月分は含めていないので、10月分の伝票番号はとんでいる。

## 動かし方

Node.js 22 以上（依存なし）。

```bash
node generate.mjs --data <入力データの出力先> --sealed <正解の出力先>
# 例（このフォルダで）
node generate.mjs --data ../../blind2-data/gen-5 --sealed ../../blind2-sealed/gen-5
```

- 固定シードで、時計と `Math.random` を使いません。何度作っても同じバイト列になります（2回作って全ファイルが一致することを確認済み）。
- 正解（`truth/lines.csv`・`truth/followup_lines.csv`・`truth/summary.json`・`notes.md`）は `--sealed` 側に書き出します。ハッシュは `SEALED.sha256`（`--sealed` のフォルダからの相対パス）。
- ソース：`generate.mjs`（本体）、`model.mjs`（マスタと価格のルール）、`catalog.mjs`（架空の商品・得意先の材料）、`output.mjs`（書き出し）、`util.mjs`（乱数・日付・CSV・Shift_JIS）。

## 利用者が知っていること

正解を見なくても、この会社（架空）の担当者なら知っていることです。

- **前回の改定日（前回の定価改定）は 2025年7月1日（令和7年7月1日）。** `R7価格改定_得意先回答一覧.csv` は、この改定に対する得意先の回答をまとめたもの。
- 2024年10月1日の定価改定は、得意先ごとの合意状況の記録がない（全得意先に適用した）。
- 2026年4月1日の改定は、仕入先の値上げを受けた**切削工具だけ**の定価改定で、得意先ごとの協議はしていない（全得意先に適用した）。合意状況のファイルはない。
- 単価は 定価 × 得意先の掛率（円未満切り捨て）、期間内の特値があればその特値。得意先マスタの掛率は、営業部で管理している取り決めの掛率。
- 粗利率の下限は社内ルールで **10%**。単価の端数処理は切り捨て。
- 数量値引は、受注時に備考へ率を書いて手入力する（例：「数量値引3%」）。
- 見本品・無償サンプルは単価0円で、備考にそう書く。`Z-` で始まるコードは運賃・手数料・値引で、商品ではない。
- 次回の定価改定は 2026年10月1日。`next/` の協議結果は、この改定に対する回答。「適用日変更」は 2026年11月1日からの適用で合意したもの。`next/単価マスタ_20261001.csv` は協議結果から作った新単価マスタ。
- 売上明細の文字コードは Shift_JIS（販売管理システムの標準の書き出し）。
