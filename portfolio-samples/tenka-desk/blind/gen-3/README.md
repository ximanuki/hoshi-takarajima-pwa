# gen-3：建材・住宅設備の卸（工務店・リフォーム会社向け）の売上データ

**このデータはすべて架空（架空）です。** 会社名（浜風建材株式会社）・得意先名・仕入先名・商品・価格・取引は作り物で、実在の企業・団体・人物・商品・取引とは関係ありません。名前が偶然一致しても無関係です。

転嫁デスク（tenka-desk）の目隠し評価（blind evaluation）用に、ほかの生成器とは独立に作ったテストデータです。入力ファイルは「架空の会社が販売管理システムとExcelから書き出したファイル」のつもりで作っています。正解（truth）は別のフォルダに封印してあり、入力フォルダには入っていません。

## 想定する会社

- 浜風建材株式会社（架空）。建材・住宅設備の卸。神奈川を中心に、本社営業部・東部営業所・西部営業所の3拠点。
- 得意先は工務店・ビルダー・リフォーム会社・設備工事店・内装工事店・販売店（二次卸）・一人親方。掛率ランクは S〜D の5段階。
- 商品は10カテゴリ（木質建材、断熱・防水材、外装・屋根・雨樋、内装建材、金物・ビス・釘、給湯・ガス機器、衛生陶器・水栓、キッチン・バス、電設・照明、塗料・接着剤・シーリング）。仕入先13社。
- 営業所ごとに商品コードの入力のくせが違います（ハイフンなし、小文字、末尾の空白、全角ハイフン、長音記号など）。

売上明細（販売管理B形式）の列：伝票日付, 伝票No, 明細No, 得意先CD, 得意先略称, 品番, 品名, 売上区分, 数量, 単位, 標準価格, 掛率, 売単価, 売上金額, 原価単価, 原価金額, 単価種別, 摘要。

- 日付は 20250106。得意先CDは半角でゼロ詰めなし（10017 など）、得意先略称は「(株)」「(有)」「(合)」つき。
- 品番は営業所ごとにゆれる（WD-2016、WD2016、wd-2016、末尾に空白、WD－2016、WDー2016）。品名と単位は半角カナ。
- 売上区分 1=売上、2=返品（数量・金額はマイナス）。単価種別 0=標準、1=得意先、9=手入力。
- 標準価格は、その日にシステムに登録されていた定価（得意先に関係なく全社共通）。掛率は 売単価÷標準価格 を出力したものです。
- 摘要は空欄が多く、現場名や「数量値引3%」「まとめ買い5%引」などが入る。全角の％や半角カナで書かれることもある。
- 運賃・荷造費・取付工賃などは、商品マスタにない商品コード（9999 など）の行として入る。

## 作り方

Node.js 22 以上。外部ライブラリは使いません。乱数は固定シードで、時計・Math.random・ロケールを使いません。

```bash
node generate.mjs --data <入力フォルダ> --sealed <正解フォルダ> [--seal-file <SEALED.sha256 の出力先>]
node verify.mjs   --data <入力フォルダ> --sealed <正解フォルダ>     # 入力ファイルだけを読み直して正解と突き合わせる自己点検
```

- `--data` に入力ファイル、`--sealed` に `truth/lines.csv`・`truth/summary.json`・`truth/followup_lines.csv`・`notes.md` を書き出します。
- `--seal-file` を省略すると、このフォルダの `SEALED.sha256` に書きます（`sha256sum` 形式、パスは `--sealed` フォルダからの相対）。確かめるには `cd <正解フォルダ> && sha256sum -c <SEALED.sha256>`。
- 同じコマンドを2回実行して、入力・正解・SEALED.sha256 がバイト単位で一致することを確かめてあります。

## 利用者が知っていること

評価でアプリを使う人は、正解を見ずに、実際の利用者が知っている次のことだけを使ってください。

1. **前回の定価改定日は 2026年4月1日（令和8年4月1日）です。** 「価格改定回答状況_最新版.csv」は、この改定について得意先ごとの回答（合意・一部合意・見送り・協議中・適用日変更）をまとめたものです。ファイル名に日付は入っていません。
2. それより前にも定価の改定はありましたが、そのときは得意先ごとの回答の記録を残していません（その改定は全得意先が新定価で請求する運用でした）。
3. 回答状況の読み方（営業事務の運用）：
   - 「適用日」が空欄なのは、改定日（4月1日）からという意味です。日付が入っているのは、改定日と違う適用日で合意した得意先です。
   - 「対象外カテゴリ」は、カテゴリ一覧のコードを `;` でつないだものです（据え置きにしたカテゴリ）。
   - 一覧にない得意先は、改定後に取引を始めた先と、改定の協議をしなかった先です（協議をしなかった先は、新定価で請求する運用）。
4. 粗利率の下限は社内ルールで **10%** です（アプリの設定で入れてください）。
5. 単価は 定価 × 掛率（円未満切り捨て）で請求する運用です。掛率は得意先ごとに、掛率ランク表の下限〜上限の範囲で決めています。
6. 数量値引は摘要に「数量値引3%」「まとめ買い5%引」のように書く運用です。見本品・サンプル・無償・試供品は、単価0円で摘要にその旨を書きます。
7. 運賃・荷造費・取付工賃などは、商品マスタにない商品コードで売上明細に入ります。現金売上（得意先コード 99999）や、取引をやめて得意先マスタから消した先も売上明細に残っています。
8. 売上明細は暦年ごとの2ファイルです。診断したいのは直近12か月（2025年10月〜2026年9月）です。
9. next/ は、2026年11月1日に切り替える次回改定の資料（新定価表、協議結果、新単価マスタ）と、11月分の売上明細です。反映チェック用です。

## 正解（封印）について

正解は `--sealed` フォルダにあります（`truth/lines.csv`、`truth/followup_lines.csv`、`truth/summary.json`、`notes.md`）。アプリを評価するまで開かないでください。`SEALED.sha256` は、評価の前後で正解が変わっていないことを確かめるためのものです。

## 注意

- 金額・数量・得意先・商品はすべて架空で、実在のものとは関係ありません。
- 実データでの精度を示すものではありません。「架空の会社の、こういう書き出し方のデータ」でアプリがどう判定するかを見るためのものです。
