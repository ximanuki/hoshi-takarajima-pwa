# ブラインド検証データ gen-2（架空）

転嫁デスクの利益漏れ判定を、独立に作ったデータで確かめるための生成器です。**データはすべて架空**で、会社名（架空ケミカル工材株式会社）・得意先・仕入先・商品・価格・取引は実在のものと関係ありません。

## 独立性

- 読んだもの：`README.md`・`README.en.md`・`data-gen/README.md` と、`public/sample/`・`public/sample/next/` の各ファイルの先頭3行だけ。
- 読んでいないもの：`src/`・`scripts/`・`docs/`・`e2e/`・`data-gen/lib/`・`data-gen/generate.ts`・`data-gen/verify.ts`。アプリとエンジンも動かしていません。
- 正解は文書のルールを解釈して決めました。文書で決まらない行は `ambiguous` にしています。

## 作ったもの

工業用部材・化学品の商社（架空）。得意先120社、商品592点、24か月（2024年7月〜2026年6月）の売上明細 21,953行。

- 2024年7月〜2025年12月は販売管理A形式、2026年1月〜6月は販売管理B形式（Shift_JIS）
- マスタ類（得意先・商品・定価履歴・原単価履歴・掛率ランク・カテゴリ・仕入先・値上げ通知）、前回改定の合意状況、特値一覧（A形式・B形式）
- `next/`：次回改定の新定価・協議結果・新単価マスタ（A・B）と、反映チェック用の2026年9月分の売上明細（B形式）1,005行

ファイル名と列は `data-gen/README.md` の形式に合わせています。

## 作り直し方

Node.js 22 以上で次を実行します。依存パッケージは要りません。

```bash
node portfolio-samples/tenka-desk/blind/gen-2/generate.mjs \
  --out    <入力データの出力先> \
  --sealed <正解の出力先（リポジトリの外）>
```

- 引数を省くと、作業用の一時フォルダ（`.../scratchpad/blind-data/gen-2/` と `.../scratchpad/sealed-tenka/gen-2/`）に書き出します。
- 乱数は固定シードで、時計・`Math.random` を使いません。何度実行しても、どのタイムゾーンでも同じバイト列になります。
- 実行のたびに、書き出したファイルを文書どおりに正規化して読み直し、正解と1行ずつ一致することを確かめます。

## 正解（封印）

正解（行ごとの判定・集計・注記）はリポジトリの外にだけ書き出します。`SEALED.sha256` は正解ファイルの SHA-256 で、開封するときに、その間に正解が変わっていないことを確かめるためのものです。

```bash
cd <正解の出力先> && sha256sum -c <このフォルダ>/SEALED.sha256
```
